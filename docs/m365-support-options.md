# Microsoft 365 support options and pilot recommendation

Prepared on 16 November 2026 for an educational project. All example questions,
content owners and results are fictional. This brief is a proposed management
discussion aid. It has not been presented to a management team.

## Question and current evidence

Which support questions can employees answer through current, reviewed guidance,
and which should reach a person? The local prototype routes questions to three
existing articles, cites the source and asks for clarification or prepares a
handover when a single current guide is unavailable. Its keyword rules are
deterministic. No AI model, Copilot service or Microsoft tenant is connected.

The twelve labelled examples cover supported questions, mixed topics, unsupported
questions and credential redaction. Matching expected answers on these examples
tests the rules. It does not estimate real-world accuracy or support savings.

## Options to investigate

| Option | Candidate use | Evidence needed before a decision |
|---|---|---|
| Existing knowledge search | Make approved instructions easier to find | Actual user tasks, search failures, owners and review dates |
| Microsoft 365 Copilot | Explore assistance within Microsoft 365 workflows | Access permissions, approved sources, user needs and applicable product requirements |
| Copilot Studio agent | Explore a scoped support assistant grounded in approved knowledge | Source quality, answer evaluation, permissions, escalation and adoption design |
| Local deterministic prototype | Establish explicit routing, citations and handover examples | Broader labelled queries and review by real support/content owners |

The prototype implements the last option. It is a baseline for discussion, not a
comparison trial of the Microsoft products.

## Proposed pilot and support organisation

1. Ask support specialists and users for recurring questions and unsuccessful
   searches. Remove personal and confidential details before preparing examples.
2. Give every proposed article an accountable owner and a review date. Agree which
   requests require identity checks, authorisation or a human decision.
3. Test one bounded use case with representative users and support colleagues.
   Compare finding the same guidance through search and through an assistant.
4. Record answer/source correctness, unsupported-question handover, completed user
   tasks and feedback. Report numerator and denominator for every measure.
5. Present findings, limitations and a prioritised recommendation. Agree owners,
   a review schedule and the next evaluation before expanding the pilot.

Suggested organisation is a shared knowledge owner, service-specific reviewers
and a support-triage route. Agile work items could cover content gaps, evaluation
failures and user feedback. No agile ceremony or enterprise rollout was performed
in this project.

## Management recommendation

Begin with content ownership and a small measured self-service pilot. Assess
Copilot and Copilot Studio against that concrete use case, using approved
sources and clear human escalation. The current evidence supports further
evaluation. It establishes no deployment benefit, adoption rate or financial
business case.
